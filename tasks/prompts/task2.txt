Feature Extension: First-Class `double_underline` Style Support and SVG/HTML Export

Problem Description:
Rich currently lacks first-class user-facing support for double underlining. Users expect to be able to use `double_underline` (along with standard aliases `double-underline` and `du`) as a style attribute, combine it with other styles (`style1 + style2`), use it in console markup (e.g. `[double_underline]text[/]`), and preserve double underlining when exporting console output to HTML and SVG.

Currently:
1. Instantiating `Style(double_underline=True)` raises a `TypeError` due to a missing keyword argument.
2. The style parser fails with `StyleSyntaxError` when encountering `double_underline`, `double-underline`, or `du` in styles or markup tags.
3. Rich's HTML and SVG exporters do not generate CSS for double underline, causing double-underlined text to lose its styling when exported.

Requirements:
1. Support `double_underline: Optional[bool] = None` in `Style.__init__`, expose a boolean property `double_underline` on `Style`, and support `double_underline`, `double-underline`, and `du` across style parsing.
2. Style addition (`style1 + style2`) and `Style.combine()` must preserve the `double_underline` attribute.
3. Markup like `[double_underline]Sample[/]` and `[double-underline red]Alert[/]` must parse and render with ANSI double-underline SGR escape sequences.
4. When exporting to HTML and SVG (`Style.get_html_style()` and `Console.export_svg()`), double-underlined styles must output valid CSS rules (`text-decoration: underline double;`), ensuring formatting is preserved in exports.
5. All existing tests must pass without regressions.
